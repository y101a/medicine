# 浏览器验收

界面验收分**两层**。原因很直接：单元测试跑在 jsdom 里，**没有布局引擎**，测不到真实排版、
弹窗层级、滚动遮挡与定位降级；而**单元测试通过不等于界面可用**。

| 层 | 命令 / 方式 | 谁看结果 | 覆盖 |
| --- | --- | --- | --- |
| 自动文字断言 | `npm run e2e` | **AI 也能读**（失败消息带选择器与坐标） | 横向溢出、弹窗几何、定位降级、异常文案 |
| 人工查看 | 起应用自己点 | **只有人能做**（需要眼睛） | 视觉观感、动画、文案是否通顺、真实联调 |

> **AI 读不了截图。** 所以自动层刻意设计成「输出文字而不是像素」：断言失败时打印的是
> `弹窗右边界 560px 超出 375px 视口（弹窗宽 560px）` 这类句子，而不是一张图。
> 截图与 trace 仍然保留（`frontend/test-results/`），那是给**人**复核用的。

## 一、自动文字断言

```powershell
cd frontend
npm run e2e
```

- 用 Playwright 驱动**本机已装的 Edge/Chrome**，不下载约 150MB 的 Chromium；
  找不到时用环境变量 `E2E_BROWSER_PATH` 指向浏览器可执行文件。
- 只启动 Vite，**接口全部由 `page.route` 拦截**，因此不依赖后端与数据库。
- 失败时附截图与 trace（在 `frontend/test-results/`），可用
  `npx playwright show-trace <trace.zip>` 回放。

**边界（必须说清）**：它验证的是「前端拿到某种响应后渲染成什么样」，
**不验证真实接口联调**。真实联调仍靠后端测试与人工跑一遍。

覆盖内容：

| spec | 断言 |
| --- | --- |
| `layout.spec.ts` | 桌面 1280px 下全部 6 个路由无横向溢出（`/app/profile`、`/app/health-records` 已并入 `/app/settings`，只保留重定向）；旧路径确实重定向到对应分栏；375px 下登录/注册页无横向溢出；固定「工作区 1000px 桌面优先约束」；窄屏提示必须出现且完整可见、桌面与登录页不得出现 |
| `settings.spec.ts` | 「模型与密钥」列出四家服务商并披露数据流向与脱敏限度；保存后只显示掩码、明文输入框消失；Key 被服务商拒绝（422）时显示服务端中文文案且不变成已配置；删除需确认，确认后回到未配置 |
| `composer.spec.ts` | 输入区说明可用输入法语音输入（如豆包输入法）并给出一次性安全提示（不要提供姓名/身份证号/住院号/手机号）；关闭提示后刷新不再出现；输入接近 2000 字上限时提醒可分多次发送；应用内语音：麦克风位于发送键左侧、首次录音先确认音频外发、取消不录音、录音→停止→转写文字进输入框且**不自动发送** |
| `attachments.spec.ts` | 附件按钮位于麦克风左侧（点开是「上传文档 / 上传图片」菜单）；首次上传先说明「解析出的文字会随问题一起交给模型」、取消则不上传也不建会话；上传成功后出现文件卡片（文件名/字数）且**不自动发送**、输入框不被文档文字灌入；点发送时请求体带 `attachmentIds` |
| `images.spec.ts` | 输入区只有一个附件按钮（在麦克风左侧）、点开是「上传文档 / 上传图片」两项，不再有独立图片按钮；**走真实路径**：点菜单 → 文件选择器 → 本地压缩 → 上传。首次上传只需勾选敏感信息与阿里云外发说明，**弹窗里没有类别选项**，勾选前不可上传、取消则不上传也不建会话；之后选图直接上传、不再弹窗；上传请求的 multipart 里**不含 `imageCategory`**、仍带 `noticeVersion`；成功卡片显示服务端自动分类的类别与对应能力边界（报告写「以纸质报告为准」）且**不自动发送**、识别结果不灌进输入框；`IMAGE_UNRELATED` 时出现可关闭短提示且**不出现卡片**；图片满 3 张后只禁用「上传图片」、文档入口仍可用；仅图片也能发送、且改用图片版默认提问（不会写成「解读病历文档」）；历史消息里的图片经鉴权接口取字节显示缩略图，已到期的显示「图片原件已按保留策略清理」且**不再请求字节** |
| `health-notice.spec.ts` | 采集弹窗完整落在视口内、三个按钮可见可点、「跳过」只提交 `noticeSeen` |
| `navigation.spec.ts` | 导航入口显示“定位仅用于本次查询，不保存”；定位三种失败（权限被拒绝 / 设备无法定位 / 超时）都给出中文说明并切到城市/区县查询；降级后能查到医院 |
| `error-text.spec.ts` | 接口返回 JSON / HTML / `detail` 数组时界面只显示中文文案；正常中文短句不被过度过滤 |

## 二、已决策：桌面优先 + 窄屏明确提示（ADR-011）

`.workspace` 带 `min-width: 1000px`，是**有意为之的桌面优先设计**。375px 下 `/app/*` 实测横向
溢出 625px（`documentElement.scrollWidth = 1000`）。**移动端已确认暂不纳入范围（ADR-011，
2026-09-18）**，但要求**明确告知用户**，不能默默撑开：

- `WorkspaceLayout.vue` 里的 `.viewport-hint`（纯 CSS 媒体查询 `max-width: 999px`）在窄屏给出
  「工作区需要至少 1000px 宽」的提示；用 `position: fixed` 是为了不被 `min-width` 撑开——
  实测 `left=0 right=375 width=375`，即**在 375px 视口里完整可见**。
- 它只挂在工作区布局上，所以已适配移动端的 `/login`、`/register` **不会**出现该提示。

守着这个决策的用例（在 `layout.spec.ts`）：

| 用例 | 断言 |
| --- | --- |
| 窄屏 375px 提示 | `.viewport-hint` 可见、含「1000」、右边界 ≤ 375px |
| 桌面 1280px | 不显示提示 |
| 登录页 375px | 不显示提示（该页已适配移动端） |
| 工作区 1000px 约束 | `.workspace` 必须已渲染且宽 1000px |

一旦开始做移动端适配，最后一条会失败，提醒同步更新本节与 ADR-011。

## 三、人工查看清单

自动化覆盖不到的部分（视觉观感、动画、文案是否通顺、真实后端联调）由人看。
截图留作记录即可，**不需要发给 AI**——它读不了。

| # | 流程 | 路径 | 要看什么 |
| --- | --- | --- | --- |
| 1 | 登录 / 注册 | `/login`、`/register` | 文案是否通顺；**直接刷新 `/register` 必须能停在注册页**（曾因 401 处理器被弹回登录页） |
| 2 | 首次采集弹窗 | 新账号登录后 | 弹窗是否被遮挡；长内容能否滚动 |
| 3 | 智能咨询 | `/app/chat` | 流式回答、自动滚动、停止生成；追问卡与病理科普卡片排版；输入区的语音输入引导与一次性提示（关闭后刷新不应再出现）、接近字数上限提醒；病历文档附件：回形针/拖拽上传、首次上传的说明确认、文件卡片与移除、历史消息里的「已删除」墓碑；图片附件：附件按钮（在麦克风左侧，点开是「上传文档 / 上传图片」）→ 上传图片、首次的敏感信息与阿里云外发确认（**没有类别选项**）、本地缩略图、卡片上服务端自动分类的类别与能力边界、仅图片发送、历史图片与到期墓碑；**语音识别必须人眼过一遍**——e2e 用的是假麦克风（只出测试音），识别质量、方言、噪声、真实药名与剂量是否转对，只能在真实联调里听 |
| 4 | 附近医院导航 | `/app/chat` 面板 | 真机定位（含真实浏览器权限弹窗）出结果后能否打开高德导航 |
| 5 | 设置 · 健康记录 | `/app/settings?tab=health`（旧路径 `/app/health-records` 会重定向过来） | 无记录时不渲染图表；有记录时三块图表与边界文案 |
| 6 | 咨询历史 / 设置 · 账户信息 | `/app/history`、`/app/settings`（旧路径 `/app/profile` 会重定向过来） | 分页、删除确认弹窗、脱敏展示；资料保存与「未保存」提示 |
| 7 | 设置 · 模型与密钥 | `/app/settings?tab=credentials` | 隐私披露是否够显眼、文案是否通顺；四家服务商条目与掩码展示；**真实 Key 保存**的验证耗时与失败提示（需要真 Key，只能在真实联调里看） |
| 8 | 真实后端联调 | 全流程 | 关停后端后各页提示是否为中文可读短句 |
| 9 | 病历文档上传（真实文件） | `/app/chat` | 用真实 PDF / DOCX / PPTX 各走一遍：解析出的文字是否与原件一致（e2e 只验证界面，**解析质量只能人眼看**）；扫描件、加密 PDF、伪装宏、超大文件、超页数各自给什么提示；删除附件后历史消息是否显示「已删除」墓碑；点「发送」后回答是否确实用上了文档内容 |
| 10 | 删除账号 | `/app/settings`（账户信息分栏） | 弹窗是否讲清后果；密码错误时是否保留登录状态并给中文提示；确认删除后是否回到登录页且旧会话失效 |
| 11 | 图片上传与识别（真实照片） | `/app/chat` | 用**不含身份信息**的测试照片走一遍：报告、片子、患处各来一张，外加一张明显无关的图和一张拍糊的图。看本地压缩后长边是否 ≤2400px、方向是否摆正（竖拍的报告不能读成横的）；看**服务端自动分类判得对不对**（无关 / 看不清的必须被拒、不留卡片、只给短提示）；成功卡片的类别与能力边界文案是否与图片实际相符；缩略图与历史消息里的图片能否正常显示、到期墓碑文案是否贴切。**识别质量与安全边界只能人眼看**——报告 OCR 是否读对、片子是否只讲影像类型/部位/可见标签/拍摄质量而不判读病灶、患处照片是否只给颜色/范围/出血等非诊断性描述并结合文字给出就诊科室。真实调用服务端阿里云视觉模型涉及费用与医疗图片外发，**必须另行确认后再做** |

## 四、2026-09-19 真实联调记录

- FastAPI 健康检查与 Vite 页面均返回 200；真实注册、Cookie 登录和 `/app/chat` 路由通过。
- 真实创建咨询并发送“你好”后，默认模型 `deepseek-v4-flash` 返回 200；历史接口读回
  1 条 `generationStatus=completed` 的 assistant 消息（202 个字符）。
- 拒绝定位后的城市查询经真实后端与高德返回医院结果。
- 授权浏览器测试坐标后，真实“前端 → 后端 → 高德”闭环返回 3 家医院，首项显示预计路线时间和距离。
- 首次实测复现附近查询 502：浏览器定位已成功，后端高德请求因 5 秒连接超时失败。
  现改为使用已配置的完整超时并对连接失败重试 1 次；修复后同一路径返回 200。
- 后端已压低 `httpx` 成功请求日志级别，避免高德 Web 服务 Key 随查询 URL 写入日志。

以上只证明本次开发环境链路可用；真实设备权限、网络和高德服务仍可能失败，前端继续保留
城市/区县自动降级。
