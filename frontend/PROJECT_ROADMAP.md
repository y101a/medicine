# 病理诊断科普助手开发路线图

> 创建日期：2026-09-03  
> 当前阶段：普通用户端咨询、红旗预检、医学检索与引用编号核验已接入；
> 以根目录 `PROJECT_PROGRESS.md` 和实际测试结果为最新进度  
> 产品边界：根据症状提供可能原因、医学科普与就医分流；不作确诊，不替代医生

当前界面范围：暂以电脑浏览器为目标，不安排手机宽度专项适配；后续需要时再恢复响应式验收。

## 1. 产品目标

建设一个支持注册登录和用户数据隔离的多用户 Web 产品。首期面向普通用户，后续再开发管理员端。

核心能力：用户认证、多轮症状咨询、危急症状分流、可信医学 RAG 与引用、LangChain/LangGraph 编排、MCP 工具、Skills 工作流，以及 ECharts 健康记录图表展示（只统计记录条数与构成，不表达病情趋势）。

## 2. 推荐技术架构

| 层次 | 推荐技术 | 用途 |
| --- | --- | --- |
| 普通用户前端 | Vue 3、Vite、TypeScript、Element Plus | 登录注册、咨询、历史、个人资料 |
| 状态与路由 | Pinia、Vue Router | 登录状态、用户信息、页面权限 |
| 图表与请求 | ECharts、Axios | 健康记录图表、REST API、统一错误处理 |
| 后端 API | FastAPI、Pydantic | 鉴权、参数校验、业务接口、SSE |
| 数据与迁移 | PostgreSQL、SQLAlchemy、Alembic | 用户、会话、消息、引用和审计数据 |
| 向量检索 | PostgreSQL + pgvector（首选） | 医学文档向量和权限内检索 |
| 缓存与任务 | Redis；任务队列按需引入 | 限流、短期状态、耗时任务 |
| AI 编排 | LangChain、LangGraph | 模型、RAG、工具与可恢复工作流 |
| 工具协议 | MCP | 标准化接入外部数据和内部工具 |
| 测试 | Vitest、Vue Test Utils、Pytest、Playwright | 单元、接口、组件和端到端测试 |

后端方案已确认采用 `FastAPI + PostgreSQL + pgvector`。

> **决策变更（2026-09-16）**：原「仅在用户确认后保存健康记录」改为「AI 自动写入，用户之后

## 5. 首批核心数据表

| 数据表 | 用途 | 隔离要求 |
| --- | --- | --- |
| `users` | 用户资料、角色、状态、注册时间 | 管理员受控访问 |
| `user_credentials` | 密码哈希、失败次数 | 不向普通业务返回 |
| `auth_sessions` | 刷新会话、设备、过期时间 | 按用户隔离 |
| `consultations` | 咨询会话与状态 | 强制按 `user_id` 隔离 |
| `messages` | 用户与助手消息 | 通过咨询归属隔离 |
| `triage_results` | 风险级别和分流原因 | 通过咨询归属隔离 |
| `sources` | 公共医学资料元数据 | 公共只读或管理员维护 |
| `knowledge_chunks` | 资料切片和向量 | 区分公共与私有空间 |
| `citations` | 回答与来源映射 | 通过消息归属隔离 |
| `audit_logs` | 登录、敏感操作、工具调用 | 仅授权管理员访问 |
