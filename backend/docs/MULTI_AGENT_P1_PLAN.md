## 前提

P0 已提供中心化流程、健康咨询的受限回答规划、科普文档的章节规划/撰写/机器复核，以及可展示的 `workflow` 契约；前端工作流图仍由 DSH 接线。P1 不绕开现有红旗分流、证据门槛、引用核验、隐私隔离和文档结构校验。模型角色不是医学审核员。

## 推荐范围与顺序

| 顺序 | 能力 | 实现边界 | 验收 |
| --- | --- | --- | --- |
| P1-1 | 有界任务计划 | 中心编排器按 `consultation`/`document_generation` 两种场景产生固定角色 DAG；模型只能在预定义节点中选择 `run/skip`，不能新增角色、工具或自由执行代码；保存计划版本与状态，不保存原始健康文本 | 非法节点/环/超步数拒绝；关闭开关沿用 P0；响应图只展示实际执行状态 |
| P1-2 | 文档分工与一次定向修订 | 内容 Agent 按章节计划生成；复核 Agent 只能提出结构化问题（无来源、引用不匹配、结构缺失），中心编排器最多将一个失败章节退回撰写一次；代码校验仍有最终否决权 | 修订最多 1 轮；失败有终态和受控错误；不能把复核意见视作医学审核 |
| P1-3 | 健康问答证据核查 | 仅在既有证据充分时，增加受限的“引用覆盖检查”角色；只能指出哪一句缺证据并请求删减，不得补医学事实或改变分流；最终仍由代码引用审计裁决 | 无证据、紧急分流和模型故障时不进入修订循环；输出不得新增来源编号 |
| P1-4 | 可恢复进度与成本护栏 | 每轮固定最大模型调用次数、超时和取消语义；文档任务持久化阶段及修订计数，咨询仅返回不含原文的工作流快照 | 重试不产生无界调用；取消后无后续调用；失败/跳过状态与实际一致 |
| P1-5 | 对照评测 | 固定合成题和文档模板，比较 P0/P1 的引用覆盖、结构通过率、失败率、延迟与模型调用次数 | 不能以自编题集宣称临床准确率；性能退化或错误新增时保持 P0 默认 |

## 不纳入 P1

- 不允许 Agent 自由选择 MCP 工具、执行任意 Cypher/SQL/代码、使用未审批外部站点，或跨用户共享记忆。
- 不做个人诊断、处方、影像判读和“模型审核通过即可发布”。
- 不新增输入框按钮；若 P1 需要用户可见的独立入口，须先确认位置并由前端所有者实现。
- 不引入队列、安装新依赖或启动本机常驻服务；先复用 P0 的 LangGraph、模型适配器和任务状态。

## 建议实施切片

1. 先冻结计划 schema、调用预算和失败语义，补纯函数单测。
2. 实现文档 P1-2，因为已有章节规划、复核与持久化任务，最容易形成可测闭环。
3. 再实现问答 P1-3；红旗和无证据分支保持原样。
4. 完成 P1-4/P1-5，并向前端交付新增节点状态契约。

首批受限版复用 `MULTI_AGENT_ENABLED=true`；默认仍为 `false`。开启后普通文字问答会先等待完整回答和证据核查，再发送正文，因此相较 P0 的逐 token 增量显示，首字等待会变长。核查模型失败时退回 P0 的代码引用核验路径并把核查节点标为 `failed`；不可把这一降级说成医学事实审查通过。
