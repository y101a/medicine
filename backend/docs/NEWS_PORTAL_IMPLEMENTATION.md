# 登录后健康资讯首页：分步实施规格

状态：2026-10-04。用户确认“先写方案、再做框架、新闻最后接入”，随后明确要求：资讯页是**同一 Vue 项目中的独立布局和路由**，不是原 AI 工作区的首页。本文取代根目录 `NEWS_FEED_PLAN.md` 中的三栏目页面布局与先采集后页面的顺序；后者的来源治理、版权、隐私和不自动进入医学知识库等安全边界继续有效。

## 1. 目标与路由

- `http://127.0.0.1:5173/` 保持进入登录页；登录成功后默认进入新的 `/portal`，采用独立的官网式页面布局，不挂在 `WorkspaceLayout` 下。已有登录后深链 `?redirect=` 仍优先，不强行重定向到资讯页；已登录用户访问 `/login` 也进入 `/portal`。
- `/app` 保持 AI 工作区，现有聊天、历史、设置和私人知识库路由不迁移。DSH 已实现的 `DashboardView.vue` 资讯原型不得直接删除或覆盖；可保留为工作区概览，或经明确迁移后复用到 `/portal`，但最终 `/portal` 不能显示工作区侧栏。
- `/app/chat` 和 `/app/consultations/:id` 保留现有 AI 对话功能；首页“与 AI 对话”按钮直达 `/app/chat`。资讯首页不是聊天页，不把新闻自动作为聊天上下文。
- 页面顶部约占桌面首屏高度一半的 AI 展示区：助手名称、名称下方的小字能力介绍、两个明显的操作按钮。介绍只描述现有能力：健康科普、医学资料辅助解释、就医方向梳理；不宣传确诊、处方或替代医生。
- “下载 Windows 版”保留入口位置，但仓库目前没有可验证的 Windows 安装包或下载地址。未交付安装包之前必须明确显示“暂未提供”，不可跳到假链接或下载网页资源冒充客户端。
- AI 展示区下方是四个分区：养生、健身、疾病、药物。点击后切换到对应资讯列表，可保留“全部”总览；分区不等于医学知识已审核。
- 分区下方是资讯卡片列表；桌面右侧独立小贴士栏，不显示工作区侧栏。小贴士须有来源或明确为空态，不得由未审核新闻推导药物剂量、疗效承诺。独立页面不受工作区 ADR-011 的窄屏布局约束，移动端改为纵向排列，不制造双重横向滚动。

## 2. 交付顺序与所有权

| 阶段 | DeepSeek（`frontend/`） | Codex（`backend/`） | 验收点 |
| --- | --- | --- | --- |
| F0 文档与契约 | 读取本文、核对现有 `/app`、`/app/chat` 和登录跳转 | 本文与 `GET /api/v1/news` 空状态契约 | 双方不得把占位内容标成当日真实新闻 |
| F1 页面框架 | 新增 `/portal` 顶层受保护路由和独立布局；登录默认跳转改为 `/portal`；迁移已完成的 AI 展示、两个按钮、四分区、列表空态与贴士位；不覆盖现有工作区 | API 只返回 `sources_not_connected` 与空数组；无迁移 | 登录进 `/portal`，页面无工作区侧栏；对话按钮进现有聊天；四分区可切换；下载按钮无假下载；“新闻源尚未接入”可见 |
| F2 数据展示 | 接 `GET /api/v1/news?category=...`，区分加载、未接入、无更新、过期、失败；卡片保留原文链接、来源与时间 | 冻结真实条目字段、分页/缓存与来源级状态；先用测试数据验证映射 | 桩和真实空态均不伪造新闻；无来源时不显示“今日更新” |
| F3 新闻接入（最后做） | 渲染真实数据并完成浏览器联调 | 先获用户确认来源策略与采集授权；逐站核对许可、RSS/接口与可用性，再实现受控拉取、去重、缓存与失效 | 实际发布日期和获取时间可见；链接可核对；来源失败不伪装成空新闻 |

F1 可以在 F3 前独立交付。DeepSeek 不直接修改后端；Codex 不直接修改 DSH 正在负责的前端文件。跨边界问题通过 `COORDINATION.md` 第 6 节交换。

## 3. API 框架契约（F0/F1）

`GET /api/v1/news?category=all|wellness|fitness|disease|medication`，要求登录 Cookie；缺省 `all`。无新闻源时固定返回：

```json
{
  "category": "all",
  "status": "sources_not_connected",
  "asOf": null,
  "items": [],
  "tips": []
}
```

`status` 未来可扩展为 `ready`、`partial`、`stale`、`failed`，但 F1 仅产生 `sources_not_connected`。F3 的条目至少包含：稳定 ID、分类、标题、短摘要、来源名称、原文 HTTPS URL、原文发布时间、系统获取时间、未经医学审核标记。无法核实发布时间就返回 `null`，不可用抓取时间冒充发布时间。新闻与小贴士分别治理；小贴士不自动从新闻生成。

## 4. 数据与医疗安全边界

- F0–F2 不联网采集、不改来源注册表、不写新闻表或正式医学知识库、不向量化、不展示虚构新闻。
- F3 优先考虑可核对的公共卫生机构、药监机构与专业组织；“全球实时”不是保证每个地区每日都有新条目，应如实显示来源覆盖、发布时间与最后获取时间。是否扩大到商业新闻 API，在 F3 前单独确认。
- 只展示标题、署名、链接和受控短摘要；不镜像全文，不收个人健康记录做推荐，不让未审核资讯自动进入 AI 医学回答。避免把新闻、养生建议或健身技巧包装成确诊或治疗建议。
- 不在用户机器注册计划任务、服务或开机自启。后续每日更新可采用页面请求时按 TTL 检查和显式前台刷新；真正的部署调度需另行设计与授权。

## 5. 验收清单

1. 路由：未登录访问 `/portal` 与 `/app` 均回登录；登录成功和已登录用户访问 `/login` 默认进 `/portal`；已有重定向深链不失效；对话按钮直达 `/app/chat`，工作区其他路由保持可达。
2. 页面：`/portal` 不显示 `WorkspaceLayout` 左侧导航；1280px 与 375px 下 AI 展示、四分区、卡片区与贴士栏不互相遮挡或横向溢出；新闻空态可见；`/app` 仍保留既有工作区导航。
3. 数据：F1 的四分类与全部分类均返回空数组和 `sources_not_connected`；非法分类 422，未登录 401；不发生 Tavily、RSS 或任何新闻采集请求。
4. 边界：Windows 按钮在无安装包时不得触发下载；无新闻时不写“今日已更新”；未审核资讯以后也不能自动升级为正式医学知识。
