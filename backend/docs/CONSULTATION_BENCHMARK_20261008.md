# 咨询链路基线与低分点（2026-10-08）

## 测试口径

本文件记录实跑结果，不把检索命中率当作医学回答准确率。首次测试使用本机开发库，`evaluate-prototype --mode keyword --top-k 3 --max-retries 0 --gate-profile current-consultation`；关键词模式不调用外部向量模型。**CLI 的 `current-consultation` 名称具有历史兼容含义：向量门槛是旧版 0.72，实际咨询图已使用 `production_relevance_gate()` 的 0.56。两者关键词门槛同为 0.2，因此下述关键词结果不受该差异影响；真实 hybrid 评测必须显式使用冻结生产门槛 0.56/0.2/0.2/0.60。**题集 `medical_retrieval_evaluation_independent.json` 共 51 道、全部标为有预期文档，题集由旧原型语料开发过程形成，不是新的盲测集。`medical_retrieval_evaluation_v5.json` 共 20 道，明确标记为开发回归题。两者分数不能代表线上混合检索，更不能代表临床有效性。

## 改进顺序与防止刷分

1. 给红旗规则补同义改写与症状已缓解的回归测试，再修复具体漏判；保持纯科普、否定、既往语境不误报。
2. 真实 hybrid 在 Top-3 与实际咨询图 Top-4 下均为 47/51。不能因关键词模式低分或 3 个低分候选就直接降低相关度门槛，否则误召回可能增加；对四道残余题先分析别名、语料表述和负例，再决定是否改检索代码。本轮不为刷已知题集分数而修改生产门槛或加入疾病推断式查询扩展。
3. 改进后在同一题集复测以量化回归，但这些题已用于诊断和改进，**不可再称为盲测或独立验收**。最终回答质量、证据支持率、响应时间、故障率需另设新题集和真实咨询链路测试。

## 已实施的红旗修复

`app/safety/triage.py` 增加了言语含糊及单侧肢体无力的受限口语模式，覆盖“说话突然含糊不清”“半边身子使不上劲”等改写，并保留否定、既往和纯科普语境的排除。新增正反例回归测试。上述两个题集共 5 道标为 `emergency` 的题，直接预检从改前 4/5 变为改后 5/5；样本太小，不宣称临床敏感度。`tests/test_triage.py` 改后 7/7 通过，Ruff 全绿。

## 回归与真实生成冒烟

后端完整 `pytest -q`：669 passed、1 skipped，用时 129.12 秒。全量 Ruff 已通过。`app/rag/consultation_smoke_benchmark.py` 使用固定公开合成问题，不创建用户、不保存聊天消息，数据库会话最终回滚；该工具不是临床正确性评分器。首轮四题：改写红旗问题直接 `emergency`、未调用模型；头晕/眩晕问题找到 2 条本地证据并调用模型（251 字）；尿路感染问题找到 3 条本地证据并调用模型（420 字）；法布雷病问题从本地缓存找到 3 条证据、跳过联网并调用模型（555 字）。后三题均得到非空文本，耗时分别约 18.2、25.0、33.2 秒。**没有人工逐句核查医学事实与证据对应，不能据此报告回答正确率。**

另用 `--case-id web_fallback_rare_disease` 单跑公开问题“庞贝病是什么？有哪些常见表现，什么情况需要就医？”：`retrieval_status=completed`、`web_search_status=completed`、3 条 prototype/未经正式审核的来源、模型调用成功、返回 509 字且含“不作确诊”提示，整轮约 56.8 秒。证明本次陌生病名的联网兜底分支实际执行；**不证明网页内容经过医学审核，也不证明回答每句均受来源支持**。

复跑真实生成冒烟必须显式传 `--allow-paid`，例如 `python -m app.rag.consultation_smoke_benchmark --allow-paid`；缺少该参数时脚本在外部调用前拒绝执行。本文结果对应参数保护加入之前的同一脚本逻辑。

本轮改进仅修复确定性红旗漏判；没有为提高已知题集分数而降低生产相关度门槛、自动提升 prototype 为 approved，或把联网摘要写成正式知识。下一轮若要给最终回答打医学正确性分，需建立全新、独立题集与逐句证据核对标准；本文件的 51 题、20 题和 5 条冒烟问题都已经暴露，不能再充当盲测。
