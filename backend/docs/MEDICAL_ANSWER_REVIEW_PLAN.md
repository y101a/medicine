# 医疗咨询生成后核查实施方案

目标：对咨询接口识别为医疗内容的模型回答，在发送给用户前完成证据核查；失败、超时或无法核查时，不发送草稿。

1. 红旗分流和既有确定性无证据回复先于模型生成执行，不额外调用核查模型。
2. 公共检索、用户选中的私人知识和本轮附件文本统一作为待核查材料。用户已明确允许把本轮选中的私人资料再次发送给所选模型核查。用户自述不额外发送给核查调用，也不充当医学知识来源。
3. 对医疗普通回答和科普卡片先缓冲生成内容，再按句号、问号、分号、逗号和换行拆成陈述单元。核查模型必须为保留的单元给出来源 ID 与原文摘录；代码验证摘录确实出现于该来源。缺少支持的单元删除，伪造摘录、正文超限、核查失败或超时则返回固定提示；不向用户输出未经核查的草稿。
4. 结构化追问卡只做格式校验，不含医学事实陈述；急症路径沿用确定性拦截。
5. 核查模型只允许通过可定位原文摘录保留原有陈述，不允许补写事实；随后继续做公共和私人引用编号核验。核查状态进入工作流事件。

验收：覆盖多 Agent 开关关闭、普通回答/卡片、私人知识、无证据、核查异常、同段混入无依据陈述、伪造来源摘录，以及未核查文本不出现在流式事件和落库内容。核查模型本身不是医学专家；摘录存在不证明它在语义上支持结论，不能承诺逐句医学真实性。

实施状态（2026-10-23）：医疗咨询核查已独立于多 Agent 开关，并覆盖卡片、本轮附件和私人知识路径；无证据、超限、核查异常均返回固定提示。本轮进一步实现陈述单元与来源原文摘录对应，并核对答案中的来源编号。结构化追问卡仍只做格式验证。判定“医疗内容”仍依赖规则门控，且来源摘录定位不能替代医学专家对真实性与适用条件的审核。

验证：咨询/私人知识相关 75 passed、10 deselected；改动范围 Ruff 通过。完整后端回归在补私人知识测试桩前为 721 passed、3 failed、1 skipped；私人知识项补桩后单独通过，另有多轮记忆测试 `test_stream_receives_old_excerpts_as_user_data_not_system_prompt` 和新闻时效测试 `test_api_reports_ready_items_and_source_statuses` 未通过。未调用真实核查模型，不能据此声称真实模型的误判率已经验证。
