# 文档表格提取验收

第一批处理 DOCX/PPTX 中真正的表格对象。每个单元格保留从 1 开始的行、列坐标；第一行不自动视为表头。供聊天附件及个人知识库检索的文本块逐行写明表格、行、列位置。合并单元格的行列对应必须标为“需核对”。

第二批对文字型 PDF 只接受严格、稳定的坐标网格：至少两行、每行 3～8 个文字片段，列起点偏差不超过 4pt，行距 8～36pt，列间距至少 25pt。2026-10-06 真实手册验收后收紧了“疑似表格”前提：相邻或隔一行的两行须构成完整、重复对齐的列网格，才允许把该局部区域当成表格候选。不满足该前提的目录、普通段落及标题保留原始正文；满足前提但内部偏移或缺格的局部区域不猜列，剔除候选行数值并提示核对原件。逐页处理，不跨页拼表。没有坐标证据的文本流依旧只是正文，不能视为已验证的表格。

| 样本 | 第一批预期 | 自动化覆盖 |
| --- | --- | --- |
| DOCX 四列表格：项目、结果、单位、参考范围 | 第二行四格坐标和内容一一对应 | `test_document_tables.py` |

| 坐标稳定的文字型 PDF 表格 | 按页面与列坐标重排行，不按 PDF 内容流顺序猜列 | `test_document_tables.py` |
| PDF 某行偏移、缺格或只剩短行 | 不产生结构化表格；候选数值不进入检索块，提示核对原件 | `test_document_tables.py` |

| 跨页表格、图片表格、复杂文字布局 | 第二批不保证结构，不能依据打平文字自动判读数值 | 后续批次待建立人工标注样本 |

验收的关键不是“提取到文字”，而是项目、数值、单位、参考范围不发生错配。本批合成样本验证坐标网格规则，尚未用真实检验报告做视觉与医学人工验收；不能据此宣称对所有 PDF 表格可靠。下一批再处理 OCR／视觉识别，并单独评估隐私、成本和医学安全。

本地非医学真实样本验收（不纳入仓库）：34 页实验手册，原始 `pypdf` 文字约 12,052 字；修复前应用解析仅 3,076 字、34 页全部误报、0 表格；修复后应用解析 11,272 字、34 个正文块、0 误报、0 表格。目录、Vivado 正文与 Verilog 文字在最终块中可检索。该样本另有 40 张内嵌图片，图片内容仍未识别；它只能验证正文保留，不能证明医学表格识别准确。

## 本地图片 OCR（已完成真实引擎联调）

- 仅 PDF 内嵌的栅格图片使用本机 `tesseract`；不调用阿里云、不外发原 PDF 或图片。部署者需安装 Tesseract 及 `chi_sim`、`eng` 语言包。Windows 会尝试从 PATH 或标准安装路径 `C:\Program Files\Tesseract-OCR\tesseract.exe` 找引擎；若项目本地 `backend/data/tessdata/` 同时含两个语言包，则优先用这份本地数据。此目录已被 `.gitignore` 排除，不随代码交付。
- OCR 文本以“图片 OCR 自动转录、未经人工核对、表格行列及单位对应未验证”单独保存；不会进入 `ExtractedTable`，不能据此推断医学报告的项目与数值配对。
- 每份 PDF 最多尝试 12 张、每页最多 3 张图片；每张最多 8 MiB / 1,200 万像素 / 3 秒，识别文字最多 4,000 字。超限、无文字或超时会留下提示，正文文字仍可用。纯图片 PDF 缺引擎或中文语言包时返回 `FILE_OCR_UNAVAILABLE`，避免只保存“未读取”提示。
- 2026-10-06 本机安装 UB Mannheim Tesseract 5.3.0 后，真实引擎从合成的中英文图片 PDF 中识别出“白细胞 6.2 Glucose 5.6”，经 `parse_pdf` 生成 1 个有“未经核对”标记的 OCR 块、0 个结构化表格。该合成样本只证明端到端链路可用，不证明复杂扫描件或医学字段的识别准确率。
- 不覆盖扫描版中的矢量图形、嵌套在不支持结构里的图像，也不负责还原图片表格结构。真实识别质量和医学字段对应须用去标识化样本另行人工验收。
