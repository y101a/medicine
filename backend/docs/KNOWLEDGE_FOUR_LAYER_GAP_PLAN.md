# 四层公共医学知识盘点、缺口与首批验收（2026-10-03）

## 结论与统计口径

先做 **4 个主题包，每层 1 个**：儿童发热、体温调节基础、合理使用抗菌药物、科学健身起步。前三个现有主题包中，儿童发热、合理用药、科学健身是**原型复核/补强**，体温调节是**新增**。不因原型可检索就认定正式医学知识已覆盖。

本次依据 `backend/data/prototype_knowledge/manifest.json`、现行开发库公共知识表、`medical_source_registry.json`、`official_summary_candidates.json` 与既有独立评测题集做盘点。未查询用户或健康记录，未重新联网核验外部来源，也未导入、向量化、审核或发布任何知识。下面的分层数量是**按原型标题/用途拟定的人工盘点**，不是数据库中已有的分类标签。

| 层 | 当前项目原型（现行） | 当前可用于正式回答的已审核文档 | 主要缺口 |
| --- | ---: | ---: | --- |
| 疾病学 `disease` | 16 篇（含常见疾病、症状、危险表现；儿童发热等 4 篇新近优先主题已有原型） | 0 | 尚无正式审核；危险表现、就医分流与症状混淆题需逐主题验收；现有独立题集未覆盖头痛/头晕、血尿/尿路感染、儿童发热、荨麻疹/湿疹 4 篇 |

开发库现状：`developer_prototype_knowledge` **26 篇现行 prototype**、**15 篇 superseded**；另有 `web_search_prototype` **7 篇现行 prototype**，它们是临时网页内容，不计入上述 26 篇稳定项目语料。两类现行原型合计 **33 篇 / 107 个知识块 / 107 个向量**；历史 superseded 文档另有 61 块，其中 3 块带旧向量，**不得算现行覆盖**。已审核 `approved` 文档 **0**，已发布图谱 Claim **0**，图谱发布任务 **0**。现有文档 `metadata.classification` 标签 **0**；四层结构已在新受控导入校验中落地，但历史原型标签仍待人工回填。

来源边界：注册表 `approved_for_ingestion` 列出 3 个来源键，但开发库内对应来源仍是 `candidate`，且逐篇审核候选 `official_summary_candidates.json` 的 10 条均为 `pending_qualified_medical_review`。**来源列入名单 ≠ 文档通过医学/版权审核**。养生健身 9 篇虽已向量化，在开发环境可检索，仍是 `prototype`；其审核边界见 `WELLNESS_STAGING.md`。

这批**不新写一份与现有原型同题的重复文档**：先对原型做事实与来源核对；确有新资料时按主题归口修订或形成新的正式摘要。生理学是唯一明确新主题。四层是用途分类，Claim/Concept 类型仍遵守图谱现有白名单；未经审核的这批内容不进入 Neo4j。

## 验收题集与门槛

机器可读题集：`medical_retrieval_evaluation_four_layer_batch1.json`，共 **20 题**，每层 5 题；`tune` **12 题**（每层 3），`holdout` **8 题**（每层 2）。SHA-256：`86B565EDB4BAFB08C7D46A42EAEE6515C58C7AB0C60BD193A2416DF18D931907`。题目用口语、情境、易混淆问法，不照抄标题。`expected_document_slugs` 目前是**原型/计划文档定位符**，不是已审核文档 ID；体温调节目标文档尚不存在。

已用现有评测模型校验 JSON：20 题、ID 唯一、四层齐全。只在当前原型库跑了 `tune` 的 **keyword/top-k=3** 零外部调用基线：**5/12 命中，Recall@3=0.4167**；生理学 3/3 未命中是缺文档的预期现象。该数字不是线上效果，也不能与先前其他题集的 hybrid 成绩横比。**未运行 holdout**，也未调阈值或调用收费嵌入。

复现开发基线（不写库、不调用向量接口）：

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.rag.cli evaluate-prototype --dataset docs/medical_retrieval_evaluation_four_layer_batch1.json --split tune --mode keyword --top-k 3 --max-retries 0
```

首批候选内容完成后的预设检索门槛：同一冻结题集下，`tune` Top-3 ≥ **11/12**；内容与检索配置冻结后只跑一次 `holdout`，Top-3 ≥ **7/8**；合计 ≥ **18/20**，且每层 ≥ **4/5**、标为 `urgent`/`emergency` 的题必须找到对应主题。未达标只在 `tune` 分析修订，若看过 holdout 后再改内容或阈值，就必须另建干净留出集，不能重复宣称这 8 题是独立验收。

检索命中**不等于回答安全或医学正确**。另需人工逐题验收这些禁止项：儿童发热不得按体温单独确诊或给未核对的个体剂量；生理机制不得被写成确定病因；抗菌药问题不得代开处方或允许共享剩药；有慢病/不适者的运动问题不得生成个人运动处方。每条回答须可追到当前有效来源，危险表现应保留及时就医分流；这些是人工医学审核项，不由上述 20 道检索题自动判定。

正式知识上线还要**单独**验证“仅 approved 来源”的检索：现有 `evaluate-prototype` 在开发环境可召回 prototype，不能拿它的分数宣称正式知识合格。正式文档 ID、版本及来源通过审核后，先固定其期望映射与只读检索范围，再做独立正式评测；当前 20 道提问文本可以复用，但不能把原型命中冒充正式通过。

## 执行顺序与停点

1. 人工确认 26 篇现行项目原型的主层/副层/主题键；对 web 搜索原型单列，不默认回填为稳定公共知识。
2. 为第一批 4 个主题逐条核对具体来源、发布日期、版本、版权条件和内容边界；缺来源的体温调节先保留候选，不编造依据。
3. 有真实合格审核人后，按受控导入元数据逐篇审核；没有审核人或权限就停在原型/候选，不改成 `approved`。
4. 只用 12 道 `tune` 做开发评测；内容冻结后跑 8 道 holdout 与人工安全核验。正式知识另跑 approved-only 评测。
5. 仅把已审核、有效证据支持且适合表达为现有谓词的关系交给图谱审核；Neo4j 是投影，不是补知识的入口。
