# AI 医学科普 Word/PPT 生成

## 边界

该能力只生成通用医学健康科普材料，不能生成或仿造病历、诊断证明、检查报告、处方、医嘱、
请假证明等医疗文件，也不读取用户上传附件、健康记录或图片来制作个体化材料。生成内容不得作
确诊或治疗依据，DOCX 和 PPTX 内均固定展示“AI 生成，未经医学专业审核”等提示。

用户必须在自然语言中同时说明制作动作、明确格式（Word/PPT，可同时选择）和医学主题。普通
聊天、否定请求、仅询问是否支持、非医学主题和受限医疗文件请求不会创建任务。用户消息先按
普通消息接口保存，服务端返回 `documentGenerationIntent`；创建任务时服务端会重新解密并复核
该来源消息，客户端不能覆盖主题。

## 处理链路

1. 创建接口校验登录用户、会话、来源消息、提示版本、格式、限额和幂等键。
2. 显式前台 worker 从 PostgreSQL 领取任务并设置租约，避免多进程重复处理。
3. 使用医学知识库混合检索获得带原始 URL 的证据；证据不足时任务失败，不让模型凭空编写。
4. 服务端固定的大模型生成受 Pydantic 约束的结构化内容计划，并验证引用编号只指向本轮证据。
5. 本地渲染器从同一内容计划生成 A4 DOCX 和/或 16:9 PPTX。
6. 校验 OOXML 真实类型、ZIP 安全、禁止对象，并用 `python-docx`/`python-pptx` 重新打开。
7. 每个文件独立加密、原子落盘并写入元数据；任务完成后才能下载。

文件正文以自编摘要为主，只允许少量短引用，并在正文与末尾参考资料中标明原始 URL。生成模型
不得看到用户自带模型密钥，配置缺失、鉴权失败、限流、供应商不可用和响应结构错误会映射为
受控错误码，不把供应商响应正文写入日志或接口。

## 配置

配置项位于 `.env`，示例和值域见 `.env.example`：

- `DOCUMENT_GENERATION_API_KEY`（为空时可回退服务端 `QWEN_API_KEY`）
- `DOCUMENT_GENERATION_BASE_URL`
- `DOCUMENT_GENERATION_MODEL`
- `DOCUMENT_GENERATION_STORAGE_DIR`
- `DOCUMENT_GENERATION_RETENTION_DAYS`（当前产品决策为 30）
- `DOCUMENT_GENERATION_ORPHAN_HOURS`（默认 24 小时安全宽限）
- 单用户并发、10 分钟和 UTC 日限额，以及检索/内容/文件大小等上限

生产环境应使用独立密钥、最小文件系统权限，并将存储根目录放在持久卷中。不要把存储目录、
模型密钥、生成正文或供应商响应纳入日志、错误详情或版本控制。

## 迁移与 worker

先升级数据库：

```powershell
.venv\Scripts\alembic.exe upgrade head
```

开发时在单独终端显式启动前台轮询：

```powershell
.venv\Scripts\python.exe -m app.document_generation_cli --watch
```

它只在该终端存活，按 Ctrl+C 停止，不会注册 Windows 服务、计划任务或随应用自动启动。单批
处理使用：

```powershell
.venv\Scripts\python.exe -m app.document_generation_cli --once --limit 10
```

worker 每轮同时处理到期清理和持久化删除任务。`--interval-seconds` 可调整显式 watch 的轮询
间隔，范围会限制在 0.5 至 60 秒。

## 保留与删除

加密文件默认保留 30 天。以下路径都会先在数据库事务内创建删除任务，再异步物理删除：

- 用户删除单个生成任务；
- 用户删除会话；
- 用户删除账号；
- worker 清理到期文件。

删除任务幂等；文件已经不存在视为成功，临时磁盘错误指数退避。下载时再次检查所有权、任务状态
和到期时间，并在解密后核对 SHA-256。

## 验收

自动化测试必须覆盖意图、幂等、越权、限额、检索证据、内容计划约束、DOCX/PPTX 重开、ZIP
炸弹与危险 OOXML、加解密、到期和删除重试。真实端到端验收会产生模型费用，因此必须由用户
明确安排；验收时至少测试单格式、双格式、证据不足、受限文件请求、跨用户下载和删除后下载。

当前实现属于开发原型。在真实模型验收和医学专业内容抽检完成前，不应对外宣称生成内容已经过
医学审核。
